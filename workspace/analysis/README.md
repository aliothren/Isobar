# analysis: results, records and figures

This folder holds what the scripts produce and the documents that carry
the results. Nothing here is edited by hand except the documents; every
table, JSON file and figure is regenerated by a script named in
[`../scripts/README.md`](../scripts/README.md).

## The frozen results (2026-09-22)

| document | what it is |
|---|---|
| [`main_config_results.md`](main_config_results.md) | the main configuration: every layout re-scored on it, the headline statistics, and a ledger giving each published percentage its numerator layout, denominator layout, absolute values and statistic |
| [`paper_numbers.md`](paper_numbers.md) | every number the paper uses, one line each, with workload, hardware, level, denominator and statistic |
| [`METRICS.md`](METRICS.md) | the registry of published quantities: which denominator each ratio has, and whether it is certified (exhaustive) or observed (searched) |
| [`mechanism_table.md`](mechanism_table.md) | the resource loads behind the ranking: why the random fills beat the distance rules and why the search beats the random fills |
| [`energy_export.md`](energy_export.md) | dynamic energy of the same frozen layouts, with the counting rule and coefficients |
| [`intra_die_correspondence.md`](intra_die_correspondence.md) | the intra-die instance: how the phase-diagram panel and the layer-level result are one instance |
| [`baseline_provenance.md`](baseline_provenance.md) | the seven placement rules: what each implements of its source and what it leaves out |
| [`baseline_traces.md`](baseline_traces.md) | replay traces of the rules on the instance |
| [`ladder_v0.md`](ladder_v0.md) | the seating ladder figure, read panel by panel |
| [`phase_diagram_isobar_caption.md`](phase_diagram_isobar_caption.md) | the phase diagram's full caption and the meaning of every marker |
| [`ANCHORS.md`](ANCHORS.md) | every published bandwidth, device and I/O figure used as a reference, with source and status |
| [`MATERIALS.md`](MATERIALS.md) | measured exhibits registered for the argument, each with its condition, generator and figure |

## The platform account

- [`SUMMARY.en.md`](SUMMARY.en.md): the account of the platform and its results, written to the stance the paper takes; the header gives the reading order.
- [`SEARCH_SPEC.en.md`](SEARCH_SPEC.en.md): the deployment search's specification, as implemented, with its accepted amendments.
- [`search_setting_design.md`](search_setting_design.md): how the search setting (instance, port ratio, bandwidths, protocol) was chosen from the phase diagram.
- [`ergodicity.md`](ergodicity.md): the annealer's move set and its reachability argument.
- [`op_breakdown/`](op_breakdown/op_breakdown.md): the per-operator cost ledger.

## The record

- [`FIXLIST.en.md`](FIXLIST.en.md): the chronological record of every model change, correction, pre-registration and result, newest at the end. When a number here and a number in a document disagree, this file says which is current and why.

## Figures

The paper figure sets are in [`figures_dac2027/`](figures_dac2027/README.md).
The standing figures in this folder (`*.png`, with `phase_diagram_isobar*` also
as PDF) are each written by one script; the figure audit of 2026-09-18
(recorded in `FIXLIST.en.md`) removed the ones whose claim had been retired
and redrew the ones whose caption lagged their data. The figure name is the
script's output name, so `grep -l <name> ../scripts/*.py` finds its generator.

## Artifacts

The `*.json` and `*.csv` files are the data behind the tables and figures,
written by the scripts and read by the tests. The most used:

| file | content |
|---|---|
| `main_config_results.json` | every layout's prefill and decode readings at 0.4 and 12.5 GB/s, kappa 2 |
| `kappa_geometry_sweep.json` | the six search cells (24x24 and 12x48 at kappa 1, 2, 4) with every run and its endpoint |
| `mechanism_table.json` | per-boundary loads, hotspots and binding resources per layout |
| `energy_export.json` | dynamic energy per layout by term |
| `objective_ablation_k2.json` | the same-budget objective ablation |
| `bw_slice_k2.json` | the frozen pair re-scored across bandwidth |
| `phase_diagram_isobar_k2.json` | the phase diagram's boundaries, envelopes and reference points |
| `simba_t1.json`, `simba_t2.json`, `simba_t3.json` | the Simba reproduction targets |
| `b_fanout_24x24_rerank.json`, `b7_s6_rerank.json` | the BookSim ranking checks |
| `intra_die_integration.json` | the intra-die layer objective at each bandwidth anchor |

Files whose names carry a version or a stage tag (`v6`, `a2_`, `b3_`, `b7_`)
belong to earlier stages of the work; the record explains each.
