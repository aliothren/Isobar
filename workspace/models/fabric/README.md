# models/fabric: the physical fabric

A fabric file declares the physical structure the package model prices:

- the levels (package, die, macro, core, crossbar), how many children each level has and in what grid;
- the link of each level, with its topology, routing, latency, energy and calibration note;
- the port model, the analog device's row time;
- the die's digital vector unit and the digital attention unit.

`scripts/fabric.py` loads and validates the files. `CIMSIM_FABRIC=<file>` selects one for a process. The device block is checked against the CiMLoop macro on every run.

| file | use in the final results |
|---|---|
| `mlx300_multidie.yaml` | the 8-macro die on which every per-operator account is measured |
| `variants/mlx300_multidie_m{4,16,32}.yaml` | the same die with 4, 16 and 32 macros (Figs. 6(b), 7(a); Table III), generated by `scripts/v4_fabric_variants.py` |
| `mlx300_multidie576.yaml` | the package the deployments start from; each configuration replaces its die mesh by its own grid |
| `mlx300.yaml` | one die: the intra-die instance of Fig. 1(a) |
| `simba.yaml` | Simba's package at its published experiment operating point (Fig. 3(a)) |
| `mlx300_multidie48.yaml`, `mlx300_3x3.yaml`, `mlx300_mesh.yaml`, `variants/*_m{2,6,8,12,24}.yaml` | earlier-stage variants, not used in the final results |
